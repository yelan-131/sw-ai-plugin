## 构建

### 1. 构建 COM 插件

```bash
cd SwComAddin
dotnet build -c Debug
```

输出：`bin\Debug\net48\SwComAddin.dll`

**注意**：`SwComAddin.csproj` 中 SolidWorks 互操作 DLL 路径硬编码为：
```
D:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\SolidWorks.Interop.sldworks.dll
```
如果你的 SW 安装路径不同，需修改 csproj 中的 `HintPath`。

### 2. 构建原生垫片（可选）

```bash
cd SwNativeShim
build.bat
```

输出：`SwNativeShim.dll`

需要 MSVC 编译环境（Developer Command Prompt）。此步仅在需要原生 COM 垫片降级时必要。

### 3. 安装 Python 依赖

```bash
cd SwAiBackend
pip install -r requirements.txt
```

依赖：`fastapi>=0.115.0`, `uvicorn>=0.34.0`, `anthropic>=0.89.0`

## 注册与卸载

### 方式 A：注册脚本（推荐）

以管理员身份运行：

```bash
cd SwComAddin
register.bat
```

脚本执行步骤：
1. `dotnet build -c Debug` — 构建
2. `regsvr32 /u SwNativeShim.dll` — 卸载旧原生垫片
3. `RegAsm /unregister SwComAddin.dll` — 清理旧注册
4. `RegAsm /codebase /tlb SwComAddin.dll` — 注册托管 DLL

### 方式 B：手动注册

```bash
# 构建
cd SwComAddin
dotnet build -c Debug

# 注册（需管理员权限）
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\RegAsm.exe ^
    bin\Debug\net48\SwComAddin.dll /codebase /tlb
```

### 卸载

```bash
# 卸载 COM 插件
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\RegAsm.exe ^
    bin\Debug\net48\SwComAddin.dll /unregister /tlb

# 或使用卸载脚本
cd SwComAddin
unregister.bat
```

## 运行

### 方式 1：COM 插件（完整体验）

1. 启动 AI 后端：
   ```bash
   cd SwAiBackend
   python app.py
   ```
   后端启动在 `http://localhost:8765`

2. 启动 SolidWorks
3. 菜单：工具 → 插件 → 勾选 "SolidWorks AI Plugin"
4. 右侧 TaskPane 出现插件面板

### 方式 2：启动脚本

```bash
start.bat
```

脚本会依次启动后端和独立 WPF 前端。注意此方式运行的是 `SwAiPlugin`（旧版独立前端），不嵌入 SolidWorks。

### 方式 3：VBA 宏启动（备用）

1. SolidWorks 中打开宏编辑器
2. 加载 `SwMacroPlugin/LaunchPlugin.vb`
3. 运行 `Main` 宏

## 发布打包

### package.bat 使用

位于 `SwComAddin/package.bat`，自动化构建→打包→生成更新清单的完整流程。

```bash
cd SwComAddin
package.bat
```

**流程：**

1. `dotnet build -c Debug` — 构建
2. 创建 `release/SwAiPlugin_vX.Y.Z/` 目录
3. 复制 DLL、依赖库、数据文件、安装脚本
4. 生成 `plugin_meta.json`（含版本号、构建时间、仓库地址）
5. 压缩为 `SwAiPlugin_vX.Y.Z.zip`
6. 计算 SHA256，生成 `manifest.json`

**产出：**
- `release/SwAiPlugin_vX.Y.Z.zip` — 完整安装包
- `release/manifest.json` — 更新清单（上传到 Release 资产）

### 发布步骤

1. 更新 `package.bat` 中 `VERSION` 变量（默认为 0.1.0，需手动改为目标版本号）
2. 按需编辑 `manifest.json` 中的 `release_notes` 和 `release_notes_summary`
3. 运行 `package.bat`
4. 在 GitHub / Gitee 创建 Release（如 v0.1.2）
5. 上传 `SwAiPlugin_vX.Y.Z.zip` 和 `manifest.json` 两个资产
6. 客户端自动检查或手动点击「检查更新」即可发现新版本

**注意：**
- `package.bat` 中 `VERSION` 需每次发版手动更新
- `manifest.json` 的 `primary_url` 默认指向 Gitee，GitHub 放在 `mirrors` 中
- `release_notes_summary` 需手动编辑

### API Key

在插件的"系统设置"页签中：
1. 输入 Anthropic API Key
2. 点击"保存"
3. 点击"验证"确认连接

或设置环境变量：
```bash
set ANTHROPIC_API_KEY=sk-ant-api03-xxxxx
```

### 后端地址

默认 `http://localhost:8765`，可在设置页签修改并保存。

### 更新配置

在 Tab5 系统设置或 `user_config.json` 中配置：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| update_source | auto | 更新源：auto（Gitee 主 + GitHub 备）/ gitee / github / mirror |
| check_interval_hours | 4 | 自动检查更新周期（小时） |
| receive_prerelease | false | 是否接收 Beta 通道版本 |
| mirror_url | null | 企业镜像 URL，非空时强制使用此源 |
| skipped_versions | [] | 用户跳过的版本列表 |
| defer_until_utc | null | "稍后提醒"到期时间（UTC ISO8601） |

**三条更新路径：**

| 路径 | 场景 | 流程 |
|------|------|------|
| 自动更新 | 有网，检测到新版本 | 下载 → SHA256 校验 → 确认 → update.bat |
| 手动选包 | 局域网，已有 ZIP | 浏览选 ZIP → SHA256 校验 → update.bat |
| 引导下载 | 局域网，未下载 | 点击 GitHub/Gitee 链接 → 浏览器下载 → 回来选包 |

## 日志

日志文件位于桌面 `SwAddin.log`，记录：
- COM 连接/断开事件
- TaskPane 创建过程
- 零件库加载状态
- 3D 预览渲染信息

**更新日志**：`%LOCALAPPDATA%\SwAiPlugin\logs\update.log`

格式为 JSON Lines，每行一条 JSON 对象：

```json
{"ts":"2026-05-14T10:30:00.000Z","level":"info","stage":"check","phase":"started","current":"0.1.2"}
{"ts":"2026-05-14T10:30:02.123Z","level":"info","stage":"check","result":"available","current":"0.1.2","latest":"0.2.0","source":"gitee"}
```

| 字段 | 说明 |
|------|------|
| ts | UTC 时间戳（毫秒精度） |
| level | info / warn / error |
| stage | check / download / verify / staging / execute |
| code | 错误码（可选，如 UPD-CHECK-NETWORK） |
| 其他 | 各阶段自定义字段 |

轮转策略：超过 1MB 自动轮转为 `update.log.1`。

## 故障排查

### 插件不显示在 TaskPane

1. 确认 `register.bat` 已以管理员权限运行成功
2. 检查注册表项：`HKLM\SOFTWARE\SolidWorks\Addins\{B3E7D8A1-4F2C-4A91-B5D6-E8F0A1C2D3E4}`
3. 查看 `SwAddin.log` 是否有 "ConnectToSW called" 记录
4. 如果日志显示 "native shim" 而非 "managed" → RegAsm 注册未生效

### 键盘无法输入

此问题仅在 TaskPane 内的 WPF 控件中出现。`SwTaskPaneControl` 的键盘钩子应已修复此问题。如果仍有问题：
- 确认焦点在输入框内（点击输入框）
- 查看 `SwAddin.log` 中是否有钩子安装相关错误

### AI 助手连接失败

1. 确认后端已启动：`curl http://localhost:8765/api/health`
2. 检查 API Key 是否已配置
3. 查看后端控制台输出的错误信息

### 标准件无法插入

`InsertBtn_Click` 使用 `OpenDoc6` 打开 `{id}.SLDPRT` 文件，需要零件文件实际存在于 SW 搜索路径中。当前版本中大部分零件的 `file_path` 为空，因此插入操作会失败。需要：
- 生成实际的 `.sldprt` 文件到正确路径
- 或修改插入逻辑使用参数化建模生成零件

### 更新检查失败

1. 确认网络可达 GitHub (api.github.com) 或 Gitee (gitee.com)
2. 查看更新日志 `%LOCALAPPDATA%\SwAiPlugin\logs\update.log` 中 `UPD-CHECK-NETWORK` 记录
3. 检查 `plugin_meta.json` 中 `update_repo` / `gitee_repo` 是否正确
4. 尝试切换更新源（设置页签 → 手动选择 Gitee 或 GitHub）

### 下载失败或 SHA256 不匹配

1. 查看更新日志中 `UPD-DL-HTTP` 或 `UPD-VERIFY-HASH` 记录
2. 下载失败会自动尝试下一个镜像源
3. 校验失败会自动删除已下载文件并重试下一镜像
4. 所有源失败后，可使用手动下载：点击 GitHub/Gitee 链接下载 ZIP，然后选择本地文件安装

### 安装后版本号未升级

1. 确认 update.bat 是否正常执行（检查 SW 是否已完全关闭）
2. 检查安装目录 `plugin_meta.json` 中 `version` 字段
3. 查看临时目录 `%TEMP%\SwAiPlugin_update\update.log` 中日志
4. 手动修复：编辑 `plugin_meta.json` 将 `version` 改为正确版本号

### RegAsm 注册失败

1. 确认以管理员权限运行
2. 检查 .NET Framework 4.8 是否已安装
3. 手动注册：
```bash
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\RegAsm.exe SwComAddin.dll /codebase /tlb
```
